# LINE 接入服务自查报告

日期：2026-10-13（Asia/Shanghai）。依据当前代码、配置和实际测试结果。
“已覆盖”只针对表中明确的代码行为，不等同于已经完成生产安全审计或容量验收。

## 1. 验证结果

- JDK 17 / Maven：`mvn verify` 成功，55 个测试，0 失败、0 错误；已生成可执行 Spring Boot JAR。
- 已使用独立 RFC 4231 向量验证 HMAC-SHA256，并覆盖原始字节篡改、中文/换行、错密钥、并发。
- Message Handler 使用 mock MessagingApiClient；Follow/Unfollow/Postback 验证实际日志，不调用外部 LINE。
- 幂等覆盖并发抢占、成功 TTL、边界、处理中保留、失败释放、容量；Webhook 测试覆盖重投递。
- SDK 双向 HTTP 联调用本地 Stub，覆盖 hello 回声、Push 相同 Retry Key 重试、409 已接受、下载和无敏感日志。
- `docker compose config --quiet` 使用虚构环境变量验证通过；缺少两个必需环境变量时校验失败。
- Docker CLI/Compose 可用，但 Docker Desktop Linux Engine 命名管道不存在，daemon 未运行：
  **未完成镜像构建与容器启动验证**。没有为了验收而开启公网隧道，也没有使用真实 LINE 凭证。

## 2. 风险与当前覆盖

| 潜在问题 | 当前状态 | 已有措施与证据 | 尚需处理/部署建议 |
| --- | --- | --- | --- |
| Secret/Access Token 硬编码、误提交 | 已覆盖配置入口，运行环境仍需管理 | LineProperties 只从 Spring 配置绑定；非空快速失败；.gitignore 排除本地环境文件；没有真实凭证夹具 | Git 历史、运维环境和人员访问不由代码保证；泄露后在 LINE 侧撤销/轮换并更新运行配置 |
| 密钥进入 Docker 镜像或构建上下文 | 已覆盖示例路径 | Dockerfile 不接收密钥 ARG/构建 ENV；.dockerignore 仅放行 pom/src/docs，并再次排除密钥文件；Compose 运行时注入 | docker inspect、管理权限和本地 .env 仍可读取；按部署平台选择 Secret 管理与访问控制 |
| SDK HTTP 日志暴露 Bearer/Reply Token、消息正文 | 已覆盖当前客户端 | 两个客户端 usingDefaultLogger(false)，wire logger OFF；DocumentedFlowIntegrationTest 捕获日志断言 | 运维改日志级别、自建拦截器、代理/隧道抓包不受该断言保护；新增客户端必须延续配置 |
| 用户信息出现在业务日志 | 部分覆盖 | 不记录消息正文、Postback data、凭证；Follow/Unfollow 按需求记录 userId，事件与消息 ID 也记录 | userId 仍是可关联标识；部署需限制日志访问、保留期，必要时脱敏 |
| Webhook 伪造/篡改 | 已覆盖签名校验 | 原始 byte[] + HMAC-SHA256；MessageDigest.isEqual；非法/缺失/不匹配签名 400；测试含独立向量 | 没有配置 Bot ID 与 destination 的额外比对，也没有主动时间窗口校验 |
| 已签名请求重放 | 部分覆盖 | 单进程 TTL 内按 webhookEventId 去重 | 验签不能防重放；重启、TTL 到期或多副本可再次处理，需 Redis/持久化状态与适合重投递的时间策略 |
| 重复消息/并发处理 | 部分覆盖 | synchronized 原子抢占、处理中保留、成功后 24h TTL、失败释放；不是只看 isRedelivery | 内存不跨实例、不持久化；Redis 实现需处理租约与释放所有权；不能宣称 exactly-once |
| Push 重试重复发送 | 自动重试已覆盖 | 首次与重试同 UUID/相同消息体；5xx/网络异常有限退避；409 有 accepted-request-id 视为成功；实际 HTTP 测试 | 用户重复调用 /internal/push 会生成新 Key；未提供外部业务幂等键与跨重启重试存储 |
| Reply Token 过期或复用 | 部分覆盖 | 即时 worker 调用；无持久化/延迟任务；排队或同批等待 >15s 跳过；Reply 不自动重试；默认单次等 3s | LINE Token 是否仍有效由 LINE 判定；远端超时后的最终执行结果未知；跳过事件当前没有补偿通知 |
| 线程池耗尽/任务丢失 | 有界控制已覆盖，可靠投递未覆盖 | 固定 4 worker，队列 256，拒绝 ERROR 日志，不在请求线程执行业务；饱和测试 | 按现有要求饱和仍返回 200，拒绝事件会丢失；生产需持久化入队后确认，或允许过载非 2xx |
| 请求体过大导致内存压力 | 未覆盖 | 队列仅限制任务数量，Controller 原始 byte[] 仍会保留请求体 | 未配置独立 JSON 请求体上限/入站速率限制；在反向代理和应用入口补大小、超时、限流策略 |
| 缓存满或高流量性能 | 部分覆盖 | 容量 10000；满时拒绝新 ID，保留有效记录 | 每次抢占同步遍历清理过期项，尚未压测；没有缓存饱和指标和自动告警 |
| 停机/重启时丢任务 | 部分覆盖 | executor 等待关闭最多 30s；Compose 允许 40s 停止；SIGTERM 直达 java | 大量积压不一定排空，强杀/崩溃丢内存任务及去重状态；需要持久队列 |
| SDK 异常与无限重试 | 已覆盖封装层策略 | 4xx 不重试；Push 默认最多 3 次、退避 200/400ms；中断恢复标记；Future 超时尝试取消；错误体不含原始 SDK 信息 | 取消 Future 不证明远端未执行；没有熔断和全局出站限流；Reply 不以 Push 自动补发 |
| 内部 Push 被外部调用/滥用额度 | 部分覆盖 | 默认关闭；启用必须有独立 token；恒定时间比较；鉴权失败 401；Compose 仅本机映射 | 当前没有 IP/网络隔离、限流、细粒度授权；整个端口经隧道公开后仍可访问该路径，应保持关闭或在代理阻断 |
| 单次消息数量与非法模板 | 已覆盖常用构造规则 | 通用封装 1..5 条非 null；文本/HTTPS 图片/简单 Flex/Quick Reply 校验；工厂 JSON 对比测试 | 通过原始 SDK Message 自行构造的其他字段仍由 LINE 验证；图片可达性、格式/大小、贴图权限未预检 |
| 文件下载内存/磁盘/连接资源 | 部分覆盖 | 流式复制、10 MiB 上限、关闭上游；不使用用户文件名；Handler 默认不自动下载 | 20s 仅等待 Future，不是整个流复制的总截止；调用方须关闭下游、删部分文件、配置可写存储 |
| 未知事件或格式异常 | 部分覆盖 | 已注册 SDK 事件策略可扩展；解析失败记录无正文的警告；空 events 正常 | SDK 不能解析的类型可能导致整批失败；HTTP 已 200，无死信或后台补偿 |
| 监控误判健康 | 未覆盖业务健康 | /health 确认进程可响应 | 不检查 LINE 凭证/可达性/队列水位，没有主动告警；Verify 也不等于 Reply 成功 |
| Docker 运行与供应链 | 示例已加入，运行未验收 | 多阶段、非 root、只读 rootfs、tmpfs、drop ALL capabilities；build 阶段执行测试 | daemon 未运行；基础镜像用 tag 而非 digest，尚未做镜像扫描/多架构验证或正式发布 |
| HTTPS 与本地隧道 | 文档已覆盖，公网未实测 | LINE 公网使用可信 HTTPS；ngrok/cloudflared 命令；本地 HTTP 由隧道终止 TLS | 临时隧道可断开/域名变化；生产需稳定 TLS/路由；第三方 Traffic Inspector 可能留存内容 |
