## 本轮实际完善内容

1. 新增 V4，建立 ai_turn/ai_turn_member 与固定消息方向/类型、用户/会话范围组合外键、稳定发送身份唯一约束及查询索引。旧 V1/V2/V3 未修改。
2. 真实迁移仅关联唯一合法 P1 正常轮，以及所有原始成员均核对一致、顺序完整且归属无歧义的第三/四阶段聚合 JSON；缺失、畸形、重复、未知来源或关联不完整的记录原样保留并排除。合法过渡轮保留 turn_id/trace，旧单成员 trace 不编造。
3. 会话所有者生成稳定 turn_id/send_attempt_id。LINE 明确接受的正常 AI 回复通过原 AsyncPersistence 在一笔业务事务中保存唯一出站、轮次和全部成员；重复提交核对同一快照后返回，不新增第二出站。缺失入站可由冻结允许业务数据补齐，已有来源、用户、内容、事件及边界冲突整体回滚，不覆盖原始记录。
4. 入站仍逐条独立尽力保存，完整允许业务元数据被复制而非引用原 SDK 对象；凭证递归移除，不进入成员快照、数据库、Redis、模型或对象打印。FAILED、UNKNOWN、提示和撤销正文不形成正常历史；事务失败不能触发重发。
5. 私聊历史改为读取权威完整关联，校验成员数量/连续顺序、来源/事件与全部成员边界；排除任何残缺轮次。消息预算按一轮全部成员加唯一回复计数，模型逐条保留 user 及一条 assistant，裁剪只能移除完整旧轮。
6. 使用 context-v2，不将旧 context 当作新格式解析；未命中 PostgreSQL 回源，旧 key 保留至原 TTL。LINE 接受后立即保留本地有界完整轮次，衔接异步落库、缓存写失败及到达截止后的间隙；P1 单条兼容模式也使用相同成功事务。
7. 清理仍遵守原独立开关，默认关闭。出站删除级联轮次，入站删除级联成员；每批清理在同一事务中另回收一批残缺轮次，不删尚未过期的剩余原始消息。新轮次存储接入 UserDataPurger；手动删除覆盖原文、新表、两代缓存、本地轮次/观察及原有状态。
8. 更新完整虚构历史 JSON，DocumentedFlowIntegrationTest 从真实数据库回源并逐字段比较角色/原文；实际下一次模型调用、发送中产生待处理轮及缓存写故障后的连续对话也验证完整历史。
9. 接口文档升级 1.5.8，变更记录、数据库设计、日志规范、P2 状态、总流程及示例步骤同步。技术提示仍默认静默，机器人聊天费用仍不作约束，未替换模型或推理配置。

## 运行与使用

保持现有 IDEA/Maven/Compose 运行方式及环境变量。升级前先停止旧活动实例并备份数据库；正常启动时 Flyway 自动应用 V4。大数据量先在离线副本测量迁移锁、耗时及空间；不要修改已应用旧脚本或同时运行新旧实例。新格式开始写入后，不直接回退不能理解多成员关联的旧二进制。

仍默认 AI_AGGREGATION_ENABLED=true、AI_DECISION_MODE=RULE、AI_TECHNICAL_REPLIES_ENABLED=false；清理默认关闭。可用虚构三条连发后接一条问题人工检查完整接话。现有持久化/缓存仍是尽力保存，不根据孤立入站或缺失出站推断没有发送，更不扫描补答。

本轮未重启或部署用户服务、未连接或迁移真实数据库、未调用真实 LINE/OpenAI；测试只使用 Testcontainers 临时 PostgreSQL/Redis、模型替身和本地 HTTP Stub。

## 剩余限制与人工复核

1. 下一阶段为第六阶段 MODEL 的 NOW/WAIT、规则回退/熔断及实际取消验证；当前仍 RULE，不能把第五阶段历史完成解释为模型时机判断上线。第七/八阶段完整关注排序、停机与负载仍待实施。
2. 进程崩溃、队列拒绝或持久化失败可能丢失记录；本地已接受轮次也会随重启消失，只能恢复已提交数据。UNKNOWN 不补发，未实现可靠入站、跨重启去重或端到端恰好一次。
3. V4 会增加约束/索引并扫描候选旧消息。真实数据量的锁、耗时和空间需要离线副本评估；迁移失败应停止启动，不跳过或改写已应用迁移。
4. 所有不满足唯一/完整关系的旧消息完整保留，但不会自动进入 AI 历史；如需人工修复历史关联，应另行确定可核对证据，不能猜测配对。
5. 人工重启后检查三条连发及下一条消息是否连贯接话；真实模型速度、收件及语义效果未由本地替身测试替代。自动清理与技术提示开关保持现有默认值。
