## 实际完善内容

1. AiChatService 默认分流至 AggregatedChatFlow，启动时互斥启用 SessionScheduler 的唯一 TurnCoordinator；P1 单条 FIFO 保留为显式关闭聚合时的兼容模式，原回归测试的断言保持不变。
2. 每条有效私聊文本先完整记录、观察入站时间并计入原 Redis 限流，再准入轮次。收集、待处理和执行资源排队分别遵守原始截止，原有技术兜底继续默认静默。
3. 新增 RULE 基线：紧急或明确完成/提问建议 NOW，继续输入或不确定内容建议一次短 WAIT；等待不占执行线程，不按标点分配多档延迟。MODEL 时机判断尚未实现，本阶段显式配置 MODEL 会快速失败。
4. ChatRequest 和 ContextComposer 保留全部当前成员的原始边界，Responses 适配器分别追加有序 user 消息，不插入未发送 assistant，不截断当前原文；输入预算只裁剪完整旧轮。
5. 正文网络重试接入协调器共享第二次请求额度，与一次撤销重生成共用首次正文截止；默认至多两次请求，SDK 自动重试保持关闭，原正文模型和推理选择保持可配置。
6. 将准入与隔离内存凭证更新放在同一状态锁内，重复、拒绝和空凭证不能覆盖已有效凭证；当前有效版本原子取得一次发送权，并转移末条有效成员的凭证与原始总截止，结束后清除引用。
7. 接入最低限度真实发送结果：明确客户端失败为 FAILED，不确定结果保守 UNKNOWN，已接受为 ACCEPTED；所有已准入成员正常完成去重，不补发或改 Push。静默有明确 TECHNICAL_SILENT 原因，不能伪造成功出站或误称为未结束作业。
8. 用户工作登记持续至实际调用、缓存/锁清理退出；删除守卫取消轮次并等待真实退出。技术提示冷却有界、可过期且接入 UserDataPurger，显式开启技术话术时各类提示共用 10s 冷却。
9. 多成员成功出站作为过渡完整保存：reply_kind=AI、in_reply_to_message_id=null、content.ai_turn 含稳定 turn_id 和全部有序业务成员；避免现有单成员查询误配。本阶段不将聚合轮写入正常历史缓存，第五阶段再补权威关联表与完整查询。单成员沿用原配对/缓存。
10. 新增 ai.turn.admitted/decided/completed 正式日志事件，先登记规范再扩展常量和白名单；生成请求保留完整成员，完成日志恢复各成员原 trace，凭证不进入日志/数据库/Redis/模型。
11. 同步默认开关、全部聚合运行变量、Compose 透传、虚构三成员入站和 Reply 示例；接口文档更新至 1.5.6，任务/实施计划和总流程骨架区分已实现与后续目标。
12. 为满足类职责和资源边界，轮次槽位数据与调用清理放回 TurnSlot/TurnExecution，协调器继续独占用户映射；未移动或重命名文件。

## 运行与使用

沿用原必需配置和 IDEA/Maven/Compose 启动方式。先停旧单实例再重启，新默认即为：

```dotenv
AI_AGGREGATION_ENABLED=true
AI_DECISION_MODE=RULE
AI_TECHNICAL_REPLIES_ENABLED=false
AI_AGGREGATION_RULE_WAIT=1s
AI_AGGREGATION_COLLECTION_SPAN=6s
```

IDEA 需在 Run Configuration 设置环境变量，Maven 在同一终端设置；仅修改 .env 不会被 IDEA/Maven 自动读取。Compose 已透传变量。显式设 AI_AGGREGATION_ENABLED=false 并重启可回退 P1。默认收集最多 8 条/4096 UTF-16 单元，不代表当前多成员必能放进模型 token 预算。完整变量和实际有效截止见接口文档 2.6。

本轮未重启用户运行中的服务、未部署、未调用真实模型或真实 LINE，未连接用户数据库，未改旧 Flyway 迁移或迁移用户数据。
