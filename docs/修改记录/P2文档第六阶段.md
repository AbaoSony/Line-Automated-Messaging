## 本轮实际完善内容

1. 新增厂商无关 TimingModelClient/TimingRequest/TimingResult/TimingFailure。策略输入包含有序完整成员、必要已接受历史、消息间隔、原轮次年龄、允许动作、原窗口余量及程序版本；不纳入草稿、凭证或 SDK 对象。
2. 使用锁定 openai-java 4.81.0 的 Responses 严格 json_schema。只允许 action/wait_ms/reason_code，校验固定枚举、整数/范围、NOW/WAIT 语义、重复/额外字段和尾随 JSON；拒绝、未完成及非法输出不作为建议，完整原响应和已知用量保留，未知为空。
3. 策略复用原模型名称，独立 reasoning=low、输入 4096、输出 1024、单次 2s、每轮最多两次机会、无自动重试；当前输入放不下则不请求模型，只裁完整旧轮，不删减原文。正文 Astra/max 和原 45s 总预算/共享两次正文请求不变，聊天费用仍不作约束。
4. 默认 AI_DECISION_MODE=MODEL，RULE 保留基线/降级。策略和正文共用唯一协调器与原工作池，策略子并发默认 1；新输入使旧判断无效，中间版本不逐片并行评估。WAIT 定时推进，额度或收集期耗尽进入 READY；模型故障用最新快照规则回退且规则最多短等一次，截止不延期。
5. DecisionCircuit 为全局常量空间状态：默认连续 5 次真实上游故障/非法响应切规则 30s，冷却后仅一探测，成功恢复、失败重新冷却；旧代次、用户取消、本地输入预检和历史依赖失败不计上游故障，不新增按用户熔断映射。
6. 入口测试复现了策略 2s 截止传给通用 Redis 获取逻辑后被再次扣除 3s Reply 预留、导致策略总被跳过的问题。所有权改用原总预算，读取和模型仍受独立策略/原收集截止；完整入口测试现已通过。
7. 验证 SDK 组合 Future 的 cancel 不自动传到底层 Future，且请求序列化可能在其他线程运行。新增受控 ModelHttpTransport 和 ModelCallScope，用随机短时标识跨异步分发关联、发起前剥除该标识；关联最多 4096，实际模型并发仍由原工作池限制。取消后等待 SDK 异步工作、真实传输及回调退出；未建立 HTTP 的迟到分发也不能发请求，不能提前归还用户/全局额度或假报删除排空。
8. 复用官方 SDK HTTP/JSON/响应/异常契约与现有 OkHttp 依赖；禁连接恢复、重定向和 503 Retry-After:0 等底层重放。策略无重试，正文仍按原应用退避和共享额度有限重试。没有修改 LINE 发送协议或增加 Push。
9. 先登记并接入 ai.decision.requested/result/fallback，原 ai.turn.decided 增加 content.source。完整允许策略输入/输出、实际模型/用量分开观测；SDK 错误仅安全类型/调用帧，不输出原始错误信封。技术提示继续默认静默，清理继续默认关闭。
10. 接口文档更新至 1.5.9，独立策略变量在 application.yml/.env.example/Compose 同步；完整虚构 NOW/WAIT 输出、任务/计划、总流程、日志及无新迁移说明同步。原文档联调和已有测试显式保留 RULE 基线，新增 MODEL 集成轨迹，全部旧断言保留。
