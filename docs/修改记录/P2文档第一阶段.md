## 本轮目标与完善内容

1. 在根规则明确聚合/判断职责及依赖方向、Reply Token 仅在当前即时内存流程有界持有、所有截止不延期、有限调用、静默和费用取舍。
2. 澄清 P1 是历史单成员规格，旧提示要求服从当前静默开关；不把 P2 规划写成已上线能力。
3. 新增 AggregationProperties 与 DecisionProperties，提供可绑定、可校验的配置契约：默认收集 6s，规划正文预留 32s；单轮 8 条/4096 字符；策略默认独立 low、2s、最多两次。配置用于资源与协议边界，不设金额目标。
4. 新增不可变 TurnBudget，复用原始 HTTP 截止和可控单调时钟；前置耗时照计，合入成员只收紧截止，预留不足关闭收集，首次正文开始后重试/重生成复用同一截止，并保留发送时间。
5. 新增镜像测试，覆盖有效/无效配置、显式装配时启动失败、旧截止成员、窗口压缩与生成时限复用。
6. 定稿 P2 实施计划：分步文件范围、未来环境映射、共享资源、成功轮次/成员表、合法 P1 迁移、异步事务、旧缓存兼容、生命周期排序及验收。
7. 更新接口文档实施状态及变更记录，明确本轮新组件没有生产装配；当前仍为 P1 单条 FIFO，真实聚合和 NOW/WAIT 尚未接入。

## 运行与使用方式

本轮配置类型和预算工具未注册到生产消息流程，无需新增环境变量或启动参数。应用继续按接口文档的现有 P1 方式运行；设置实施计划中的未来环境变量不会自行启用聚合。

后续协调器接入时，以首条 HTTP 原始 Deadline 创建 TurnBudget，合入成员时保存 including 返回的新预算，首次正文开始时保存 beginGeneration 返回的新预算；重试/重生成不得重新创建初始预算。该工具不替代状态机、调用记账或发送权控制。
