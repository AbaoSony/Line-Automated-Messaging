## 本轮实际完善内容

1. 新增 V5，为 line_user 保存原 lifecycle_received_at、lifecycle_sequence、lifecycle_event_id，完整排序一起存在或一起为空。未修改 V1～V4；旧值和消息保留，不为旧数据编造排序。先比较 LINE 事件时间，同时间比较冻结接收微秒/序号；最后同事件 ID、同时间重投递和未知旧排序保守保持。实际设备顺序不作保证。
2. 新增有界 UserLifecycleQueue，关注变更和 active 私聊短时准入对同用户串行，统一查询 PostgreSQL，避免额外关注缓存与数据库分叉。复用原业务持久化池，入口全体在途/排队最多 line.persistence.queue-capacity，当前默认 512；不同用户可并行。仅等待状态读取及短时准入，不等待模型或网络发送。
3. 原文与观察先独立记录，再异步确认关注状态；明确取消关注、依赖/容量拒绝及过期均静默结束，未建立用户状态行仍允许聊天。HTTP 继续快速 200，后台失败安全记录，不要求 Webhook 重试；记录仍是尽力队列，不宣称可靠入队。
4. 仅权威状态有效变更为取消关注才触发单向 UserLifecycleListener，取消未发送轮次、待处理轮次、定时及策略/正文。旧/重复事件不取消当前会话，重新关注不复活旧版本；旧调用尚未实际退出继续占资源，新消息可能仍按原关闭/容量规则静默拒绝。
5. 逐条兼容任务增加运行取消标记和中断；迟到模型即使最终返回也不能恢复发送。当前短时 MDC 绑定本地 AI 取消代次，逐条正文及排队技术提示在发送租约处原子核对；代次不进入业务表、Redis、日志或指标。原文及真实发送结果记录不受取消代次阻止。
6. 准入继承原 HTTP 截止，独立单线程计时器释放过期的待准入回调/凭证；数据库实际未退出时仍保留容量和用户工作租约，不假报删除排空。没有延长聚合、正文或发送截止，模型/推理、45s 总预算、默认技术静默和默认关闭清理保持。
7. 手动删除等待新增短时入口及实际调用，验证删除期间不能回填，成功后新消息使用新历史；超时与 Redis 仍有所有者时明确失败、保留/回滚数据库，恢复后可以幂等重试。Redis 不属于 PostgreSQL 本地事务，不宣称跨存储原子回滚。
8. 自查发现连续删除的审计竞态：上一轮删除审计原来绕过工作计数，可能在下一轮删除后迟到回填。先补 RecordQueueTest 复现旧实现失败，再修复为本次删除事件/审计可在自己的屏障内登记，但持有实际写入租约；下一次删除等待上一轮记录退出后再清理。审计仍异步、有界，失败不覆盖删除结果。
9. 完整停机分阶段：定时保留清理实际结束 → Webhook 上游排空 → 生命周期短时入口结束 → AI 取消未发送/定时，SENDING 与提示共用一个总预算收尾 → 依赖工作结束及实际用户工作核实 → 业务持久化排空 → 事件/审计刷出 → 资源销毁。复用原单线程定时清理用途，未改变清理默认开关。
10. UserWorkDrain 在持久化关闭前检查实际用户工作；取消 Future 或轮次终态不代表本地传输已退出。执行器/定时清理无法在预算内结束明确输出 shutdown_not_drained 并报告失败；不能据此保证远端停止或突发崩溃可靠恢复。
11. 接口文档更新到 1.5.10，新增完整虚构 refollow 示例；文档联调先确认 UNFOLLOWED，再 refollow 确认 FOLLOWING/清空 unfollowed_at，然后保留原 hello 完整出站断言。新增一次请求后精确计数为 13，没有删除或放宽既有出站、原文、去重和凭证断言。

## 运行与使用

继续通过 IDEA 或 Maven 启动。升级前先停止同 Channel 旧单实例并备份，在副本评估 V5 的迁移锁与耗时，再正常启动自动执行未应用迁移。没有新增环境变量或依赖；原 OPENAI_MODEL/OPENAI_REASONING、MODEL/RULE、技术静默与保留清理开关沿用原配置。

有效取消关注只保留数据并取消未发送工作；重新关注后发送新消息，不自动恢复旧问题。内存轮次、短效凭证与取消代次不持久化，重启不扫描只有入站而没有出站的记录补答，不自动改用 Push。

本轮没有启动、部署或重启用户实际服务，没有迁移真实数据库，也没有请求真实 LINE/OpenAI。所有自动验证使用虚构数据、临时 PostgreSQL/Redis、本地 HTTP Stub 或模型替身。
