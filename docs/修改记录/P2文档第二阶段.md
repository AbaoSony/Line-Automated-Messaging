## 本轮完善内容

1. 新增有序文本成员、作用域内只读快照和共享缓冲账本，保留完整原文、时间、顺序及成员各自 trace，不接收凭证或 SDK 对象。
2. 实现每用户最多一个活动轮次和一个待处理轮次，覆盖 DECIDING、WAITING、READY、GENERATING、SENDING 及 ACCEPTED/FAILED/UNKNOWN/EXPIRED/CANCELLED/REJECTED 终态；冻结待处理轮次后拒绝第三轮。
3. 绑定会话代次、轮次、输入/正文版本与调用序号；旧判断、旧正文和迟到定时不能恢复已取消轮次或取得发送权，同一判断只能应用一次。
4. 复用第一阶段不可延期预算，区分语义等待、等待前轮和 READY 执行资源排队。无新输入也能定时推进；规则最多等一次，策略最多两次调用，不用新消息或晋升重新计时。
5. 实现有界执行队列、共享工作线程与策略子并发，正文优先，其他 READY 用户按队列顺序轮转；队列/定时拒绝返回明确业务结果，不回退调用者执行外部工作。
6. 预留第二个正文请求时与撤销重生成共用轮次额度和首次生成截止；旧调用实际退出前不能启动重生成。后续真实模型适配仍需接入共享额度接口。
7. 原子核对版本并进入 SENDING，同一轮只有一个发送权赢家。已经发送中的工作按真实结果或 UNKNOWN 收尾，不假报取消，不再次取得发送权。
8. 取消实际执行只请求中断，保留其在途和快照资源直到 TurnWork 返回并完成清理；取消尚未开始的排队作业使用原子认领，迟到执行不能重复归还资源。每轮最多三个定时引用，取消后移除队列引用。
9. 在现有 SessionScheduler 增加一次性的空闲模式切换，轮次模式与逐条模式互斥；复用原工作池、定时池、删除守卫及停机入口。默认生产 AiChatService 尚未调用该切换。
10. SessionScheduler 注册为 UserDataPurger，新增轮次状态由守卫先取消、排空后回收；如果仍有该用户工作，purge 立即失败，不在事务内等待或假报删除。
11. 补充可控时钟、真实线程与同步屏障测试，验证取消/清理竞态、旧结果、一次发送权、资源容量、公平性、模式互斥、共享额度及停机。先用回归测试复现“建议已应用且唤醒后，在旧调用仍清理时被重复应用”的问题，再增加单次应用检查修复。
12. 同步 P2 状态、实施计划、接口文档 1.5.5 及数据库设计的删除扩展说明；未把模拟执行当作生产聚合已启用。

## 运行与使用方式

当前应用继续按接口文档的 P1 方式启动，无需新变量。技术提示开关仍默认 `AI_TECHNICAL_REPLIES_ENABLED=false`。生产入口尚未调用 enableTurns，因此本轮部署后真实连发仍不会自动合并，已有 3s 逐条排队行为继续存在。

后续第三阶段在启动装配中启用唯一轮次模式并实现 TurnWork：先逐条保存/限流再准入，接入规则基线、真实正文调用和用户工作跟踪；不能同时走旧 submit。发送结果分类、未知后重投递、多成员历史及完整生命周期继续按第四阶段及之后验收。

单独验证组件可执行：

```powershell
mvn "-Dtest=TurnBufferTest,TimingDecisionTest,TurnCoordinatorTest,TurnLifecycleTest,TurnResourceTest,SessionSchedulerTest" test
```

完整回归需要可用 Docker Engine：

```powershell
mvn clean test
```
