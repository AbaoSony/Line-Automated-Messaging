> 方案方向已确认：采用“有界语义等待 + 可靠会话执行”，将 P4 的最小 NOW/WAIT 判断提前到 P2。
> 当前实施状态：前七阶段已交付，生产默认启用 MODEL 时机判断、聚合、真实正文及完整多成员权威历史；RULE 保留基线/异常回退，生命周期已接入，综合/负载与真实体验仍待第八阶段。数据流见 [总流程骨架](总流程骨架.md)。
> 当前接口、配置和行为以 [接口文档](接口文档.md) 为准；路线与数据流见 [总流程骨架](总流程骨架.md)。
> 运行参数、第七阶段已实现范围及限制见 [接口文档](接口文档.md)；后续目标参数见 [P2 实施计划](P2实施计划.md)。场景示意全部虚构。

## 一、目标与范围

对 active 一对一 USER 文本建立有界会话轮次：短时间连发可合并为一个输入快照，模型建议现在回复或短暂等待补充，程序执行截止、取消、限流、资源约束和最多一次 Reply 尝试。

核心验收仍为：**连发合并、预算不重置、不重复回复**。“不重复”指单进程去重有效范围内的一轮一次发送尝试，不承诺跨重启或端到端恰好一次。

不再以“标点决定等待 1.5/2.5/3.5 秒”作为主要产品策略；规则策略保留用于基线比较、配置降级和模型异常回退。取消固定窗口的主导地位，不等于取消定时唤醒、收集上限或硬截止。

| 纳入 P2 | 留在后续阶段 |
| --- | --- |
| 进程内存缓冲、一个活动轮次和一个待处理轮次 | 持久化延迟任务、重启续发 |
| REPLY_NOW / WAIT_FOR_MORE、有界规则回退 | DEFER_REPLY / END_TOPIC / NO_REPLY 等完整行动决策 |
| 有限撤销、版本检查、发送终态与去重衔接 | 自动 Push 补发、分钟级等待、主动联系 |
| 多入站与单回复关联、历史迁移 | 长期记忆、角色生活、图片生成 |
| 删除、有效取消关注、停机收尾、成本评估 | 多实例、群聊 AI、多模态聚合 |
| 可靠即时执行 | 拆气泡、打字延迟、Loading Animation、引用回复 |

沿用单活动进程、PostgreSQL 权威存储、Redis 可丢弃缓存/锁/限流；不新增 Redis 用途、依赖或中间件。仅用 Reply，不增加对外 HTTP 接口。

必须明示的边界：

- “不无限等待”是模型不能无限延期、轮次有终态；不是模型或网络故障时仍保证收件。
- 保持 `AI_TECHNICAL_REPLIES_ENABLED=false`：生成失败、忙碌、限流、依赖故障、输入过长默认静默。只有显式启用才发送技术话术。
- Webhook 沿用快速 200；入队拒绝可能丢任务，异步持久化可能丢记录，不提供可靠入站或恢复队列。
- 不靠更新 Token 延长已有成员预算，不用其他成员 Token 或 Push 补发结果未知的回复。
- 自然度以连贯性、接话分寸和相关性评价，不以故意拖延、编造现实活动或误认真人为验收指标。

## 三、架构与状态所有权

### 3.1 分工与依赖

| 模块 | 职责 |
| --- | --- |
| webhook | 原始字节验签、有序接入、事件去重与路由 |
| ai 编排 / coordination | 唯一会话所有者、准入、状态、时钟、资源、版本、终结与取消 |
| ai/aggregation（拟新增） | 有序成员、不可变快照、容量与合并规则，不持有会话映射 |
| ai/decision（拟新增） | 厂商无关策略契约、规则策略、建议校验，不直接发送 |
| ai/generation | 策略与正文模型适配、超时、取消、用量，隔离厂商类型 |
| ai/memory、chat | 已接受完整轮次、短期缓存、权威历史与异步事务 |
| messaging | 发送校验、一次 Reply、明确失败与未知结果表达 |
| user、common | 复用删除屏障、持久化、日志、审计与指标 |

依赖：`webhook → ai 编排/coordination → aggregation、decision、generation、memory`；编排继续依赖 chat/user/messaging。generation 可以实现 decision 定义的契约，decision 不反向依赖 generation。aggregation 不依赖协调器/发送层；common 不依赖业务包。

等待使用有界定时事件，不占模型线程，不创建每用户线程，不用长时间 sleep。状态锁内不做网络/数据库 I/O；复用并扩展现有调度、记录与删除设施，不另造一套并行会话状态。

### 3.2 核心对象（规划名称，不代表已有类）

| 对象 | 必需信息 | 约束 |
| --- | --- | --- |
| Session | Channel/user、session_epoch、活动/待处理轮次、生命周期边界 | 唯一所有者，无引用后有界清理 |
| InboundMember | eventId、messageId、原文/业务元数据、事件/接收时间、序号、traceId、原始截止 | 无凭证，保持逐条边界 |
| Turn | turn_id、成员、首条时刻、硬/收集截止、状态、input_version、调用额度 | 不因新消息、晋升或重生成重置 |
| DecisionAttempt | attempt_id、绑定版本、调用截止、结果和用量 | 版本由程序绑定，模型不能声明自己有效 |
| GenerationAttempt | generation_version、冻结快照、共享生成截止、物理请求计数 | 重试与重生成共享额度和截止 |
| SendAttempt | send_attempt_id、一次发送权、reply_kind、终态 | 生成成功不是发送成功 |
| TokenHandle | 本轮最新合格令牌及其接收时刻 | 仅当前内存流程，不进业务快照/模型/持久化 |

session_epoch 用于生命周期失效，不因下一轮收到消息就使当前合法生成失效；当前轮次 input_version 仅在其成员变化时递增。全部回调核对会话代次、轮次和版本，不得在删除后重建旧状态。

### 3.3 状态机

| 状态 | 含义 | 新消息处理 |
| --- | --- | --- |
| DECIDING | 有额度和预算时执行时机判断 | 可合入则更新版本/dirty 标记，不逐片并发判断 |
| WAITING | 有效 WAIT 已裁剪并登记唤醒 | 合入后重新评估，旧唤醒失效；无新消息也会到期推进 |
| READY | 决定回复，等待执行资源 | 收集未截止且未冻结时可合入，不重置排队起点 |
| GENERATING | 对冻结快照生成 | 仅满足撤销条件才合入重生成，否则进下一轮 |
| SENDING | 原子取得发送权，准备/正在调用 LINE | 一律进下一轮，已发起远端请求不可撤回 |
| ACCEPTED | LINE 已接受，保留 reply_kind | 终态，不再生成/发送 |
| FAILED | 明确失败或生成/依赖失败，记录阶段 | 终态，不由重投递自动重启 |
| UNKNOWN | 不能排除已发送副作用 | 终态，不补发，不进成功历史 |
| EXPIRED / CANCELLED / REJECTED | 截止、生命周期、准入或容量拒绝 | 释放引用，分别记录原因，不伪造出站 |

每用户最多一个活动轮次和一个待处理轮次。待处理轮次从自己的首条接收计时，收集截止到达即冻结，不能等前轮结束后再计时；晋升时检查剩余预算，不重新等待。待处理已满或冻结时按容量拒绝新事件，不创建无界第三轮。

终态与清理幂等。每轮定时引用有界，取消任务移除队列引用；迟到回调丢弃。控制事件需预留容量或有界合并，不能因普通消息队列满而丢失发送完成、截止、删除通知。清理不得回退执行模型、发送或日志写库。

## 四、接收、准入与连发

1. 原始字节验签后有序发布到有界接收队列，快速返回 200；不等待 Redis、数据库、模型或 LINE。
2. 异步按请求发布顺序、同请求 events 顺序解析和分配序号；分配与发布一致，不能只 AtomicLong 自增后允许线程乱序入会话。顺序以本服务为准，不承诺设备原始发送顺序。
3. 先去重，再逐条提交原始入站记录，然后做有效文本限流与容量准入。首次见到 isRedelivery=true 仍检查资格；重复不重复计数/入轮。
4. 限流由当前“任务执行时”前移到“轮次准入前”，每条有效文本计一次。Redis I/O 不放 HTTP 线程，受限时长；若并行化准入，结果仍按同用户序号发布，不能按返回速度重排。
5. 收集期合入活动轮次，冻结或发送后进入待处理轮次。未准入、重复、无可用令牌事件不得替换当前令牌；无令牌记录并终结，不用它延长预算。
6. 加入前校验条数和字符数；达到边界立即冻结。下一条会超限时尝试待处理轮次，再不足则拒绝。单条自身超限按 INPUT_TOO_LONG，不截断原文。
7. 准入拒绝仍尽力记录可解析原始入站；全局接收拒绝、崩溃、落库失败仍可能丢记录。
8. 非文本不加入、不延长也不提前结束文本等待；群聊、聊天室、standby、无 userId 保持现有行为。文本后发图可能出现分离回复，明确为体验限制。

## 五、时机决策与回退

### 5.1 契约

输入为不可变业务快照：有序当前成员、必要的已确认近轮历史、消息间隔、轮次年龄、状态、允许动作与最大等待。未发送草稿不进入 assistant 历史；用户文本保持 user 角色，不拼入 system 指令。所有凭证、原始请求头/体、SDK 对象禁止入模。

| 输出字段 | 要求 |
| --- | --- |
| action | 仅 REPLY_NOW 或 WAIT_FOR_MORE |
| wait_ms | NOW 为 0；WAIT 为有限正整数，不超过本次允许上限 |
| reason_code | 固定枚举 COMPLETE_INPUT / POSSIBLE_CONTINUATION / USER_REQUESTED_WAIT / URGENT |

不要求自由文本推理过程，不允许模型输出可执行命令、收件人、凭证或调度权限。严格校验结构、枚举、类型、长度与数值；非法值回退规则，合法建议再受当前剩余时间裁剪。模型自报版本不能作为有效依据。

策略复用当前模型名称与厂商适配，推理独立默认 low，输入保守预算 4096、输出上限 1024，均可配置；这些是请求资源边界，不是费用目标。负责人确认所有聊天费用暂不考虑，不设金额上限。不能假设 2 秒内一定完成，不能擅自引入快模型；策略失败或预算不足按规则回退，正文配置保持独立。锁定 SDK 4.81.0 的结构化输出已核对，第六阶段已用本地 HTTP Stub 验证实际请求、结构校验及取消行为；真实模型延迟/质量仍未验证。

### 5.2 调用与唤醒

- 每轮最多两次物理策略调用，无策略自动重试；超时、无效、被替代调用仍计数。
- 同用户策略与正文不并行启动多个本地请求。策略进行中只更新快照/dirty 标记，中间版本不逐个评估。
- 返回版本过期则丢弃；有额度且仍在收集期才评估最新快照，否则规则回退或 READY。
- 有效 WAIT 登记一次版本化唤醒。新消息可重新判断，但不能延后固定收集截止；到期没有新消息也须重新判断或 READY。
- 到收集截止、容量上限或决策额度耗尽时停止模型等待。策略调用超时与收集截止取更早者，不越界等结果。

### 5.3 规则与熔断

提供 MODEL / RULE 模式；MODEL 为目标能力，RULE 为可比较基线和降级，不是关闭聚合。

规则采用可控时钟的纯函数：完整/催促倾向直接 READY；可能补充或无法判断时短等一次，候选 1 秒，受首条起收集截止约束。每轮规则等待最多一次，新消息不能滚动续命。词表面向台湾繁体口语，其他语言走默认策略，不能把标点当作真实意图保证。

策略超时、无效、拒绝、额度耗尽后，对最新合法快照按规则推进；收集已截止直接 READY；依赖不可用或预算不足则分类终结。规则回退决定何时正常生成，不自动恢复技术话术。

已实现全局熔断基线：连续 5 次超时/无效/上游失败切 RULE 30 秒，冷却后只放一个有预算的探测；成功恢复，失败继续冷却。版本过期和用户取消不计上游故障。采用全局有界状态，不无界创建按用户熔断器。

## 六、时间与资源预算

### 6.1 不变量

单调时钟用于进程内截止，墙钟用于业务记录。每条 `D_i` 从所属 HTTP 入口原始接收时刻计算。

```text
D_turn = min(全部成员 D_i, 首条接收时刻 + 最大存活时间)
C_turn = min(首条接收时刻 + 最大收集跨度,
             D_turn - 排队/依赖预留 - 正文生成预留 - 发送预留)
wake_at = min(当前时刻 + 合法建议等待, C_turn)
D_generation = min(D_turn - 发送预留, 首次正文生成开始 + 模型阶段上限)
```

C_turn 不因新消息、规则回退、晋升活动或重生成延后；剩余预算不足时只可提前。到期立即冻结收集。预留是规划参数，不保证模型耗时；每阶段实际等待仍取剩余时间与阶段上限的较小值。

重试和重生成共享同一个 D_generation；下一轮排队照计；更换令牌不延长已有成员预算。到总截止不再发起调用，已发起发送按实际结果或 UNKNOWN 收尾。

### 6.2 已定稿实施基线（分阶段接入）

以下由配置契约与实施计划承接。第三阶段已装配聚合、RULE 规则及技术提示冷却，运行参数见接口文档；第六阶段已装配策略模型参数及熔断，当前默认 MODEL；第七阶段已接入完整生命周期，综合/负载和真实体验仍待第八阶段。

| 规划项 | 候选值 | 约束 |
| --- | --- | --- |
| 轮次最大存活 | 沿用入口总预算 | 默认 45 秒、上限 50 秒，不另加等待 |
| 最大收集跨度 | 6 秒 | 包含策略、上下文与中途重算，从首条 HTTP 接收起 |
| 排队预留 / 执行队列等待上限 | 3 秒 | READY 等资源的年龄；不能提前杀死合法 WAIT |
| 协调/依赖预留 | 1 秒 | 规划值，实际所有前置耗时照计 |
| 正文生成预留 | 32 秒 | 用于限制收集，不保证模型实际完成 |
| 发送预留 | 3 秒 | 沿用原边界 |
| 策略单次 / 物理调用上限 | 2 秒 / 2 次 | 第六阶段已接入，还受收集截止限制，无隐式重试 |
| 规则等待 / 次数 | 1 秒 / 1 次 | 不滑动续命 |
| 正文物理请求总上限 | 2 次 | 网络重试与输入变更重生成共用 |
| 最大撤销重生成 | 1 次 | 可设 0，仍需处于收集期且剩余预算足 |
| 单轮成员/字符 | 8 条 / 4096 UTF-16 单元 | 加入前校验，先达者生效，不截断 |
| 每用户轮次 | 1 活动 + 1 待处理 | 不把旧 3 条任务队列照搬成 3 轮 |
| 会话 / 待执行作业上限 | 1024 / 256 | 准入、在途、等待分别计量 |
| 全局缓冲 | 2048 条 / 200 万 UTF-16 单元 | 覆盖活动/待处理及保留快照；实际内存需压测 |
| 全局本地模型在途 / 策略子上限 | 4 / 1 | 共用总额度，正文优先 |
| 熔断 | 5 次连续失败、30 秒冷却 | 第六阶段已接入，全局有界、单探测 |
| 技术提示冷却 | 10 秒 | 显式启用时生效，失败/未知也占机会 |

预算账本：收集/决策 6 + 排队 3 + 协调/依赖 1 + 正文 32 + Reply 3 = 45 秒。前置或阶段额外开销继续压缩正文，不能再叠加完整的模型 40 秒上限。策略输入/输出上限与参数映射已补齐于实施计划；TurnBudget 验证收集压缩与总/正文截止不延期，；状态和共享正文请求额度由 TurnCoordinator 负责，实际 SDK 本地传输取消已在第六阶段验证；远端是否停止不能据此推断。

配置拒绝负值、无界资源和不能满足发送预留的组合；预留导致收集跨度压缩时明确展示有效值。删除等待、墓碑、锁 TTL 和停机等待必须一起核对。

### 6.3 记账与取消

- 接收/准入队列、成员、快照、会话、定时引用、待执行作业、模型在途和提示冷却全部有界。
- 内容复制不得绕过总字符约束；共享快照按保留关系记账，字符数不等于 JVM 堆占用或模型 token 数。
- 取消 Future 不证明远端停止/未计费；尚未结束本地传输或清理的请求继续占额度，未知用量不记零。
- 正文重试占用了第二个名额后不能再重生成；若名额用于重生成，新生成不能重新获得两次尝试。
- 4xx 含限流不重试；5xx/网络/超时仅在共同截止及额度允许时有限退避，关闭 SDK 隐式重试。
- 满载明确拒绝并终结，不回退到 HTTP/定时线程执行模型/发送；不能不断取消以伪造空闲资源。

## 七、生成、发送与去重

### 7.1 冻结与撤销

正文使用冻结的有序成员和已确认历史，当前输入只出现一次，保留原文、消息边界、必要标识与事件时间，所有成员保持 user 角色。

生成中收到消息，只有在 C_turn 前、容量允许、仍有重生成及物理请求额度、剩余预算足时，才能原子失效旧版本并合入；旧调用结束本地清理后安排新调用。否则消息进下一轮。旧输出不发送、不写上下文、不记成功出站，已知用量仍保留。

生成完成后核对版本、会话代次、删除屏障、所有权、截止、内容与一次发送权；“校验版本 + 进入 SENDING”原子完成。禁止校验后由未经再次核对的闭包发送。发送层继续注册删除跟踪并检查剩余预算。

已发起远端请求不可撤回；取消/截止不能把 SENDING 假报成未发送。不能宣称本地检查与 Redis/LINE/PostgreSQL 构成跨服务原子事务。

### 7.2 凭证边界

仅用本轮最新、通过准入且具备合格令牌的成员 Token；旧引用释放且不再使用。下一轮、拒绝、重复、无令牌事件不得覆盖。可用性最终由 LINE 判断，本地只检查资格和年龄。

令牌只在当前有界接收/轮次/发送内存路径存在，不入数据库、Redis、日志、detail、模型、恢复任务或对象打印。终结/替换释放业务引用，不声称安全擦除 JVM/SDK 全部副本。

### 7.3 终态与去重

| 结果 | 发送/去重动作 | 历史动作 |
| --- | --- | --- |
| 正常 AI 被 LINE 接受 | 全体成员保留消费状态，轮次终结 | 异步保存完整成功轮次，更新已发送上下文 |
| 技术提示被接受 | 占本轮或该拒绝事件唯一发送机会 | 保存提示，不进正常历史 |
| 明确失败 | 保留终态，不自动换令牌重做 | 无正常成功轮次 |
| 发送超时/中断/不能排除副作用 | UNKNOWN，不再 Reply/Push，保留消费状态 | 无正常成功轮次，保留安全原因 |
| 生成被替代 | 成员仍属原轮，去重不释放 | 旧输出不入历史 |
| 接受后缓存/持久化失败 | 不释放为可重新执行事件 | 可能缺记录，不能靠重发修复 |
| 静默/拒绝/取消/过期 | 明确终结已消费事件 | 原始入站尽力保留，不伪造出站 |

已准入 AI 轮次通过明确业务终态完成上游 CompletionStage，不把业务失败直接映射到 Webhook 通用异常释放。真正未准入、无副作用的基础设施失败是否释放须单独定义测试；不改其他 Handler 通用行为掩盖 AI 问题。

处理中去重不提前过期，终结后按有界 TTL 保留，不驱逐有效记录换新容量。内存去重不能保证跨重启、TTL 之后或多实例不重复；入站唯一索引不等于发送幂等。

### 7.4 技术提示

默认静默只记录入站、错误、分类和 SKIPPED，不产生提示 attempted/accepted、出站或伪造模型用量。

显式启用后：未准入事件只用自己的令牌，已准入轮次的生成故障提示消耗本轮唯一发送机会。BUSY、RATE_LIMITED、SERVICE_UNAVAILABLE、INPUT_TOO_LONG、FALLBACK 共用用户级固定冷却，从尝试起计时，失败/未知也占用，不随新消息延期。冷却结构有界且过期清理，容量不足保守抑制。提示经协调器安排，不争抢正常轮次状态；SENDING/UNKNOWN/ACCEPTED 后绝不追加提示。

## 八、轮次持久化与上下文

1. 完整正常历史轮次 = 同批次一条或多条入站文本 + 已获 LINE 接受的一条正常 AI 回复。FAILED/UNKNOWN 等可以留业务事件，不是成功历史。
2. 新增 Flyway 迁移表达成功轮次和有序成员关系，计划明确表名、主外键、唯一约束及查询/清理索引。使用稳定 turn_id、出站幂等标识和成员会话范围唯一归属，不按相邻行猜测。
3. 原始入站逐条异步保存。成功出站、轮次、成员在同一异步业务事务提交；为处理入站落库乱序，可幂等补齐允许的原始成员再写关联。失败整体回滚，不能暴露半轮，也不阻止/重发 Reply。
4. 失败、技术提示、撤销输出及来源未知记录保留但排除正常历史。查询只返回完整轮次；裁剪最旧完整轮次和请求预算，不改存储原文。
5. P1 有明确合法配对的数据迁为单成员轮次；缺失、歧义和重复配对保留原记录并排除，不猜测。部署/旧版本兼容与大数据量影响在实施计划说明，禁止修改已应用迁移。
6. last_chat_gap 以本轮首条之前为边界，排除全部当前成员与后续轮次；无历史与读取失败继续区分。
7. 有界内存快照衔接尚未落库的上一轮，只有正常 Reply 被接受后纳入；缓存写失败不重新执行，快照遵守删除和版本边界。
8. Redis 历史用格式版本或新命名空间，旧格式回源、旧 key 依 TTL 淘汰；删除覆盖新旧命名空间。仍为原缓存用途，不新增任务存储。
9. 保留清理与手动删除覆盖轮次/成员；部分成员被清理后不返回残缺轮次，明确删除顺序或级联约束。

## 九、生命周期与重启

### 9.1 删除和关注状态

复用 UserWorkTracker/UserDataDeletionService：事务外阻止新工作，清空等待/待处理轮次，失效定时和决策/生成版本，取消可取消调用、释放凭证引用；等待已发起发送、真实仍在途调用、业务持久化及事件/审计排空，再事务内调用全部 Purger。超时明确失败，不假报删除成功。

会话代次/墓碑阻止旧结果在屏障解除后回填，新请求可建立新历史。新缓冲、冷却、关联表接入清理。Redis 不受数据库回滚保障，清理失败支持幂等重试。

有效取消关注只改状态并取消未发送工作，不删历史。先按事件时间判断新旧，旧重投递不能取消重新关注后的会话；同时间冲突规则在计划明确并测试，不声称还原设备顺序。SENDING 记录真实收尾，不能撤回。

### 9.2 停机与恢复限制

优雅停机：关闭准入 → 取消未发送轮次/定时/生成 → SENDING 限时收尾 → 业务生产者结束及持久化排空 → 事件/审计刷出 → 关闭资源。突然崩溃不保证有终止日志。

重启只恢复已持久化合法历史；内存轮次和令牌引用丢失，不继续发送，不扫描“只有入站、没有出站”的记录补答。没有出站记录不能证明没发送，可能在 LINE 接受后、落库前崩溃；丢本地引用也不等于 LINE 自动让令牌失效。

### 9.3 后续 P4 恢复边界（未实现，不计 P2 验收）

分钟级等待/续发需另行确认：持久化任务、发送意图、取消代次、原始到期时间、累计调用额度、稳定 Push Retry Key、请求体冻结及恢复规则；Reply Token 始终不持久化。

“恢复已提交任务”不等于“全部 HTTP 200 可恢复”，后者必须改变可靠入站和失败确认语义。允许丢弃的日志队列不能承载可靠任务状态。

恢复时 Reply 发送中/未知不改 Push；已接受不重发；Push 未确认仅在平台支持范围内复用原 Key 和完全相同请求。新消息使旧计划失效，但不能假称未知在途发送已取消。跨重启使用持久化绝对时刻并保守处理时钟偏差，不能序列化 System.nanoTime。

## 十、日志、指标和成本

新增事件实施前先登记 [日志规范](日志规范.md) 与 detail 白名单，再增加 LogEvents，接入后才标已触发。以下只是候选名称，尚未登记/实现：

- `ai.decision.requested/completed/failed`：实际业务输入、结构化建议、版本、耗时、已知用量、固定失败原因；不记录隐藏推理或 SDK 信封。
- `ai.turn.ready/superseded/finished`：冻结原因、成员数、等待时长、撤销数、终态与安全原因。
- 发送未知可独立登记或扩展既有失败事件原因；保持现有数据库 outcome 枚举兼容，不直接写未支持的 UNKNOWN outcome。

白名单补 turn_id、input_version、generation_version、调用类别、次数等。成员保留各自 trace_id/eventId/messageId/序号；固定主 trace，通过成员关联追溯，不能用最新消息的 MDC 覆盖所有入口。标识不作指标标签。

允许完整业务内容，凭证禁记。沿用独立日志池、有界队列、丢弃计数和安全兜底，不同步阻塞业务。

指标覆盖轮次大小、等待/总时长、终态、策略/正文调用、回退/熔断、撤销、未知发送、资源水位、拒绝和每个成功轮次的实际用量。未知用量不伪造零成本。

用相同虚构或经授权输入轨迹对照 RULE/MODEL：提前接话率、同语义段拆轮率、撤销率、首条至 LINE 接受 P50/P95、放弃/未知比例和人工连贯性评分。费用与实际用量仅观测，不作为准入或验收门槛。策略频繁超过 2 秒或挤占正文时先降级/重新确认模型，不通过延长总预算掩盖。

必测矩阵：

- 正确/错误/缺失签名、快速 200、接收拒绝、有序发布竞争、同请求顺序和多用户公平。
- 单条、生成前三条、持续连发、待处理收集过期、第三轮拒绝、条数/字符/全局容量、空缺令牌不替换。
- NOW/WAIT、无新消息定时推进、连续 WAIT、非法结构/越界/未知动作、规则仅等一次、熔断单探测。
- 决策进行中新消息、旧判断返回、迟到定时；仅最新合法版本可推进。
- 新消息/重生成/更新令牌/晋升不重置截止；策略消耗正文预算，排队及前置事件年龄照计。
- 重试与重生成共用两次物理请求，策略最多两次；取消不绕过额度，迟到结果无成功副作用。
- 生成完成与新输入/删除竞争，一次发送权只有一个赢家；SENDING 新输入进入下一轮。
- Reply 明确失败/超时/未知后重投递，所有成员不重发；缓存/持久化失败不重新消费。
- 静默无提示 attempted/accepted/出站；显式启用共享冷却，失败/未知也占机会，不借批次令牌。
- 非文本/群聊/standby 范围、有效取消关注、旧事件保护、删除超时/清理重试/新历史。
- 单成员迁移、残缺/歧义保留、事务回滚、异步乱序、旧缓存回源、清理及全部 Purger。
- 多 trace 汇合可追踪且无线程串扰；完整业务原文保留，凭证不进日志/数据库/Redis/模型/对象打印。
- 停机顺序、崩溃不承诺可靠恢复、重启不扫描无出站记录自动补发。
- 扩展 DocumentedFlowIntegrationTest 精确核对单条、连发、静默、未知结果重投递和关联，保留原凭证断言。

每轮实际修改按 AGENTS.md 生成独立记录。代码交付须 `mvn clean test` 全部通过；未执行或失败如实说明，不能宣称完成。
