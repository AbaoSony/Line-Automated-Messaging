# 日志规范

已按本次确认替换原脱敏要求：运行日志、event_log、audit_log 允许完整保存用户标识与业务内容。
不实现 UserRefHasher，不要求 LOG_USER_REF_KEY，不截断、不匿名化用户数据。
仓库中的示例和测试仍只能使用虚构数据，不得提交真实用户记录。

## 实施状态

- 已实现：应用 stdout 使用 Spring Boot 内置 Logstash JSON；异步落库失败包含 event、trace_id、user_id、operation、error_type；落库线程池传递已有 MDC。
- 未实现（步骤 2）：全链路 trace_id 生成/清理与响应头、现有日志全部事件化、统一固定字段、本地额外易读日志文件。
- 未实现（步骤 3）：event_log、audit_log、事件队列/批写/独立连接池、审计和指标 HTTP 端点。

## 凭证边界

禁止记录或存储 Channel Secret、Access Token、内部接口 token、API Key、数据库密码、
replyToken、quoteToken、markAsReadToken、完整签名或包含它们的原始请求头/完整 Webhook 请求体。
可以记录完整 `user_id`、消息原文、回复和非文本业务元数据。按字段选择内容，禁止直接打印 SDK 事件对象。
JDBC/SDK 异常可能携带凭证，当前落库失败日志只输出异常类型，不输出异常消息或绑定参数。

## 字段

| 字段 | 含义与状态 |
| --- | --- |
| event | 使用 LogEvents 已登记常量 |
| trace_id | 链路 ID；当前落库无 MDC 时生成失败记录 ID，全链路传递步骤 2 完成 |
| user_id | 原始完整用户标识，无用户上下文时可为空 |
| operation | 失败的持久化操作事件名 |
| error_type | 异常类名，不包含凭证 |
| ts、level、service、env、version、instance | 统一字段命名和默认值步骤 2 完成 |
| webhook_event_id、outcome、duration_ms、http_status、message_type、content | 步骤 2/3 按业务记录，content 保留完整允许业务数据 |

## 固定事件登记

以下名称已一次性登记于 `common.logging.LogEvents`。登记不代表当前全部事件已经触发。

| 类别 | 事件 |
| --- | --- |
| 用户 | user.follow、user.unfollow、user.message.received、user.postback |
| Webhook | webhook.received、webhook.signature_invalid、webhook.duplicate |
| LINE | line.reply.sent、line.reply.failed、line.push.sent、line.push.failed、line.retry |
| 基础设施 | executor.rejected、persist.failed |
| 审计 | internal.push.invoked、user.data.deleted |
| 保留 | chat.retention.cleaned |
| 后续阶段 | user.rate_limited、ai.generate.success、ai.generate.failed、ai.fallback.used、memory.cache_miss、lock.timeout |

ERROR 表示需要人工介入；WARN 表示已处理但需关注的重试、拒绝或兜底；INFO 表示关键业务事件。
生产 DEBUG 默认关闭。新增事件必须先登记本文并增加常量，禁止直接拼接事件名。

## 保留与排查

聊天、事件日志、审计日志分别配置独立清理开关，默认关闭；启用时默认保留 90/30/180 天。
当前仅聊天清理已实现。事件/审计保留将在步骤 3 实现。
当前可在 JSON stdout 中按 trace_id 检索落库失败；联合 event_log 的查询示例在步骤 3 完成。
本地易读文件会遵守相同凭证边界，并保存在 Git 忽略目录，步骤 2 接入。
